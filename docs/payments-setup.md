# 결제 설정 — 토스페이먼츠 키 넣는 법

> 코드는 준비돼 있고 **키만 넣으면 결제가 열립니다.**
> 키가 없는 동안에는 카드 버튼이 잠기고 "카드 결제는 아직 준비 중입니다"가 뜹니다.
> 계좌이체 신청 경로는 그대로 작동합니다.

---

## 1. 계약과 키 발급

1. [토스페이먼츠](https://www.tosspayments.com)에서 전자결제를 신청합니다. 사업자등록증이 필요합니다.
2. 심사가 끝나면 개발자센터에서 **클라이언트 키**와 **시크릿 키**를 받습니다.
3. 키는 두 벌입니다 — **테스트용**(`test_`로 시작)과 **라이브용**(`live_`로 시작).
   먼저 테스트 키로 확인하고 그다음 라이브 키로 바꿉니다.

---

## 2. 키를 넣는 곳

### 클라이언트 키 (공개되어도 되는 값)

프로젝트 루트의 `.env` 또는 `.env.local`에 넣습니다.

```
VITE_TOSS_CLIENT_KEY=test_ck_여기에_클라이언트_키
```

빌드 시점에 화면 코드로 들어갑니다. **바꾼 뒤에는 반드시 다시 빌드하고 배포해야** 반영됩니다.

```bash
npm run build
npx wrangler deploy      # 전역 CLAUDE.md §15-2 토큰을 환경변수로 물린 상태에서
```

### 시크릿 키 (절대 공개 금지)

Google Secret Manager에 넣습니다. 코드나 저장소에 적지 마십시오.

```bash
printf '%s' 'test_sk_여기에_시크릿_키' | \
  npx firebase functions:secrets:set TOSS_SECRET_KEY --project sungpan2026 --data-file -
```

> **지금은 자리표시 값이 들어 있습니다.** `TOSS_SECRET_KEY`에 `NOT_CONFIGURED`가 저장되어 있고,
> 서버는 이 값을 보면 결제를 열지 않습니다. firebase가 시크릿이 아예 없으면 함수 배포 자체를
> 막기 때문에 자리만 만들어 둔 것입니다. 위 명령으로 실제 키를 넣으면 그때부터 작동합니다.

넣은 뒤 **함수를 다시 배포해야** 반영됩니다. 함수가 시크릿 버전을 배포 시점에 고정하기 때문입니다.

```bash
FUNCTIONS_DISCOVERY_TIMEOUT=120 npx firebase deploy \
  --only functions:createPaymentOrder,functions:confirmPayment
```

## 3. 확인

1. 업체 계정으로 로그인해 **AI 업무 자동화** 화면에 들어갑니다.
2. 캐럿 팩의 **카드로 충전**이 눌리는지 봅니다(키가 없으면 잠겨 있습니다).
3. 테스트 키 상태라면 토스가 제공하는 테스트 카드번호로 결제해 봅니다.
4. 결제 후 `/payment/success`로 돌아와 "결제가 끝났습니다"와 충전된 캐럿 수가 보이면 정상입니다.
5. Firestore `agencies/{업체}/payments/{주문번호}`의 `status`가 `paid`인지,
   `agencies/{업체}`의 `aiCredits.purchased`가 늘었는지 확인합니다.

## 4. 구조 — 왜 이렇게 만들었나

### 금액은 서버가 정합니다

화면은 상품 종류(`kind`)와 상품 ID(`itemId`)만 보냅니다. 금액은 서버가 자기 표를 보고
정해서 주문에 저장하고, 승인할 때 그 값과 대조합니다. 다르면 승인하지 않습니다.

이걸 어기면 화면에서 값을 바꿔 1원으로 결제하는 공격이 통합니다.

### 상품 정본은 서버입니다

- 캐럿 팩 — `functions/src/payments/toss.ts`의 `CARAT_PACKS`
- 마케팅 서비스 — 같은 파일의 `MARKETING_SERVICES`

**화면 가격을 고치면 서버도 함께 고쳐야 합니다.** 서버에 없는 상품 ID로 결제를 시도하면
"없는 서비스입니다"로 막힙니다. 상품 ID는 화면(`MarketingCenterPage`의 `SERVICES[].id`)과
같아야 합니다 — `naver-seo`, `local-content`, `aeo-geo`.

### 중복 지급을 막습니다

결제 후 새로고침하면 승인 요청이 두 번 들어올 수 있습니다. 주문 상태가 이미 `paid`면
아무것도 하지 않고 반환합니다.

### 주문 문서는 서버만 씁니다

`firestore.rules`에서 `agencies/{aid}/payments/{orderId}`는 **읽기만** 허용합니다.
화면에서 금액이나 상태를 고칠 수 있으면 검증이 무의미해집니다.

## 5. 아직 없는 것

| 항목 | 상태 |
|---|---|
| 정기결제(빌링) | 없음. 블로그 월 10만원도 지금은 1회 결제입니다 |
| 환불·부분취소 | 없음. 토스 관리자 화면에서 수동으로 해야 합니다 |
| 웹훅 수신 | 없음. 승인은 사용자가 돌아온 시점에만 처리됩니다 |
| 세금계산서 | 없음 |

**웹훅이 없어서 생기는 일** — 사용자가 결제 직후 창을 닫으면 승인이 안 된 채 남습니다.
토스는 일정 시간 뒤 자동으로 취소하므로 돈이 빠져나가지는 않지만, 주문은 `pending`으로
남습니다. 운영하면서 `pending`이 쌓이면 웹훅을 붙여야 합니다.
