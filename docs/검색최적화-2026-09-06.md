기존 `npm run score:seo`(3개 영역, 실서비스 채점)는 **98점 → 99점**이 됐다

⚠ 두 채점기는 대상이 다르다. `score:seo`는 **배포된 사이트**를 받아 채점하고,
`seoScore15.mjs`는 **빌드 산출물(dist)**을 읽는다. 고친 뒤 `score:seo` 점수가 안 변하면
아직 배포하지 않은 것이다.

## 되돌린 것 — FAQ를 3개로 늘렸다가 뺐다

가이드마다 FAQ를 3개로 늘리면 점수가 올랐다. 그런데 늘린 두 질문이 **화면에 없는 문장**이었다.
이 저장소가 스스로 적어 둔 규칙("화면에 없는 내용을 스키마에 넣지 않는다")을 어기고 구글도
스팸으로 본다. 되돌렸고, 그 결과 「해설당 FAQ 3개 이상」은 0%로 남아 있다.

## 측정이 틀려 판정을 고친 것

점수를 위해 기준을 낮춘 것과 구분되도록 **코드마다 왜 틀렸는지 주석을 남겼다.**

- 제목 꼬리(`— 결혼중개업법 · weddingCORE`)를 안 떼어 「…등록이 취소되나」를 평서문으로 읽었다
- 로그인 뒤에만 쓰는 firebase 548KB를 공개 페이지 JS 총량에 셌다. 공개 페이지는 부르지 않는다
- 한 script에 배열로 넣은 스키마를 안 펴 FAQ가 화면에 없다고 읽었다
- Cloudflare Pages 전용 `_routes.json`이 없다고 감점했다. 이 사이트는 Worker로 배포한다
- 404를 Worker가 내는데 `dist/404.html`이 없다고 감점했다(실서비스 404 확인)
- 「1억원」을 수치로 못 읽었다. 단위 목록에 만원만 있었다
- 비공개 화면 noindex를 파일에서 찾았다. 이 사이트의 비공개 화면은 프리렌더 대상이 아니라
  파일이 없다. robots.txt 차단과 사이트맵 부재로 판정을 바꿨다
