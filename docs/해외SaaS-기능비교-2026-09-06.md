# 해외 결혼중개 SaaS에는 있는데 우리는 없는 것 (2026-09-06)

비교 대상은 **SmartMatchApp**(미국, 매칭 CRM, 사용자당 월 $30)과 **인도계 matrimonial/marriage
bureau 소프트웨어**(MatchFinder DX, Logicspice, GoClixy 등)다. 인도 제품군이 우리와 가장 가깝다.
중매인이 후보를 관리하고 손님에게 소개하는 구조가 국제결혼중개와 거의 같다.

우리 기능은 **코드에서 직접 확인했다.** 있다고 적힌 것이 실제로 도는지까지 본 것은 아니다.

---

## 1. 한눈에 — 없는 것 15가지

| # | 해외에 있는 것 | 우리 | 이 사업에 필요한가 |
|---|---|---|---|
| 1 | **후보 명부 + 검색·필터** | 고객에 매달린 상대방만 | **1순위. 없으면 매칭 기능 전체가 죽어 있다** |
| 2 | **프로필 사진·영상** | **사진 필드가 아예 없다** | **1순위. 국제결혼 중개는 사진이 전부다** |
| 3 | 계약서 생성 | 「계약 검토」만 있고 작성은 없다 | **높음. 법 제10조 서면계약 의무** |
| 4 | 손님에게 줄 인쇄물(바이오데이터) | 매칭 제안서만 인쇄된다 | **높음. 신상정보 서면 교부가 법정 의무** |
| 5 | 역할별 권한 화면 | 저장 규칙엔 있고 화면이 없다 | **높음. 직원 둔 업체는 쓸 수 없다** |
| 6 | 회원 포털(손님 로그인) | 없음 | **낮음. 아래 3절 참조 — 베끼면 안 된다** |
| 7 | 캘린더·일정 관리 | 기한 목록은 있고 달력이 없다 | 중간 |
| 8 | 이메일·SMS 대량 발송·자동 알림 | 접수 알림 문자 1종(사장에게만) | 중간. 동의 문제가 따라온다 |
| 9 | 수수료 청구·인보이스·환불 기록 | 캐럿 충전·마케팅 결제만 | 중간. 법 제10조 환불조건과 이어진다 |
| 10 | 보고서·분석 | 대시보드 카드 몇 개 | 낮음. 대부분 1~3인 업체다 |
| 11 | 조건 기반 자동 매칭 추천 | 점수는 있으나 후보가 없어 무용 | 1·2번 뒤 |
| 12 | 네이티브 모바일 앱 | 설치형 웹앱(PWA)은 있다 | 낮음 |
| 13 | 업무 화면 다국어 | 손님용 도구만 4개 언어 | 낮음 |
| 14 | 앱 내 통화(번호 숨김) | 없음 | 낮음 |
| 15 | 외부 서비스 연동 | 없음 | 낮음 |

## 2. 큰 구멍 다섯 — 왜 그것부터인가

### (1) 후보 명부가 없다
해외 제품은 후보를 **독립 데이터베이스**로 두고 나이·지역·학력·직업·종교로 걸러 낸다.
우리는 `agencies/{id}/clients/{clientId}/partners/{partnerId}` — **한국인 고객 밑에 매달린 상대방**만
있다. 그래서 "이 손님에게 맞는 후보를 찾는다"가 불가능하고, 매칭 화면에 상대 이름을 손으로 친다.

MBTI 궁합·사주 점수를 만들어 두고도 늘 비어 있는 이유가 이것이다. 이미 두 곳에서 같은 지적이 나왔다
(예행연습 08-1, 인수인계 문서의 P1).

### (2) 프로필에 사진 필드가 없다
`ClientProfile`에 키·몸무게·학력·종교·취미는 있는데 **사진이 없다.** 국제결혼 중개에서 손님이
가장 먼저 보는 것이 사진이다. 신상정보 서면에도 사진이 들어간다. 서류 업로드로 우회할 수는 있지만
그건 증빙 서류함이지 프로필이 아니다.

### (3) 계약서를 만들어 주지 않는다
자동화 문서 6종은 개인정보 제3자 제공 동의서, 출입국 보완요청 대응서, F-6 신청 패키지,
국제결혼중개 계약 **검토**, 체류기간 연장 패키지, 체류자격 변경 검토다.
**계약서 작성이 없다.** 그런데 서면계약은 법 제10조 의무이고 우리 타임라인이 그걸 추적하고 있다.
"해야 한다"고 알려 주면서 "만들어 주지는 않는" 상태다.

### (4) 손님에게 줄 종이가 안 나온다
인쇄되는 것은 매칭 제안서와 비자 준비도 결과뿐이다. **신상정보 서면은 인쇄가 안 된다.**
제10조의2는 서면 제공을 요구하고, 우리는 화면에 번역·서명·제공기록까지 만들어 두고도
정작 건넬 종이를 못 뽑는다(예행연습 06-3과 같은 지적).

### (5) 직원을 넣을 수 없다
저장 규칙에는 owner·manager·staff·readonly 네 역할이 있는데 **초대하는 화면이 없다.**
직원이 있는 업체는 대표 계정을 같이 쓰거나 못 쓴다.

---

## 3. 해외에 있어도 베끼면 안 되는 것

**회원 포털(손님이 로그인해 프로필·사진을 스스로 관리)** — 해외 제품의 대표 기능이지만
우리 손님은 다르다. 실태조사에서 50세 이상이 30.8%이고, 현장 인터뷰에서도 사장이 노트로
관리하는 시장이다. 손님에게 계정을 만들라고 하면 대부분 안 한다.

같은 필요를 채우는 우리 방식은 이미 설계돼 있다 — **문자 링크로 여는 진행 현황판**
(`docs/진행-현황판-설계.md`). 로그인 없이 "지금 어디쯤"만 보여 주는 화면이다. 이쪽이 맞다.

**앱 내 통화·네이티브 앱·업무화면 다국어**도 이 시장에서는 값이 낮다.
설치형 웹앱은 이미 되고, 외국인 배우자가 우리 업무 화면을 볼 일은 없다(신상정보 번역은 이미 6개 언어).

---

## 4. 반대로 — 우리에게 있고 그들에게 없는 것

기능 수로 지면 안 되는 이유가 여기 있다. 이건 베낄 수 없는 쪽이다.

| 우리 것 | 해외 매칭 CRM |
|---|---|
| 결혼중개업법 42개 의무를 고객별 타임라인으로 자동 전개 | 없음 |
| 조문 15편·법령해석·재결례 32편을 화면에서 연결 | 없음 |
| 신상정보 번역(6개 언어)·서명·제공기록 | 없음 |
| F-6 비자 요건 엔진과 국가별 규정 | 없음 |
| 변호사 검토 큐(승인 전 제출 금지 표시) | 없음 |
| 규제 변동 레이더(법령 개정 자동 수집) | 없음 |
| 성평등가족부 공시 업체 자동완성 | 없음 |

해외 제품은 **짝을 맺어 주는 도구**이고 우리는 **처분을 막는 도구**다.
기능 목록을 따라가다 이 축을 잃으면 값이 비싼 해외 제품의 열등한 복제가 된다.

---

## 5. 그래서 무슨 순서로 만들 것인가

전화 영업(`docs/업체-영업계획-2026-09-06.md`)에서 사장들이 실제로 무엇을 묻는지 들어 보고
정하는 것이 가장 정확하다. 그 전에 정하는 잠정 순서는 이렇다.

1. **후보 명부 + 사진** — 둘은 한 덩어리다. 명부 없이 사진만 붙여도 소용없다
2. **직원 초대·권한 화면** — 저장 규칙이 이미 준비돼 있어 화면만 만들면 된다. 값싸고 효과가 크다
3. **신상정보·프로필 인쇄물** — 이미 있는 데이터를 종이로 뽑는 일이다. 법정 의무와 직결
4. **계약서 작성** — 표준약관을 확인한 뒤. 변호사 검토가 앞선다
5. **캘린더 뷰** — 타임라인 데이터를 달력으로 다시 그리는 것
6. **수수료 청구·환불 기록** — 결제는 이미 붙어 있으니 기록부터

**2번을 1번보다 먼저 해도 된다.** 값이 싸고 지금 쓰는 업체가 바로 덕을 본다.
