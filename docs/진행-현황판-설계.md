# 진행 현황판 설계 — 계약 손님이 "지금 어디쯤인지" 스스로 보는 화면 (2026-09-04)

상태. **설계 확정, 구현 전.** 손님 심리 리서치 3단계 항목이다. 우리결혼중개 계획서는 이것을
"weddingCORE 연계 여부까지 함께 정한다"고 우리 쪽에 넘겼고, 데이터가 전부 weddingCORE에 있으므로
엔진이 제공하는 것이 맞다. 결혼중개 트랙과 비자 연장 트랙에 같은 화면을 쓴다.

## 1. 왜 만드나

- 손님 심리 5번 「통제감 상실 두려움」. 생애사 연구 참여자의 말 그대로 "비행기를 딱 타고 나니까 걱정이
  되기 시작하는 거예요." 계약 뒤부터 입국까지 몇 달 동안 손님은 업체가 다 알아서 한다는 말만 듣는다.
- 업체 입장에서는 "지금 어떻게 되고 있어요?" 전화가 줄어든다. 대표 한 사람이 월 30명을 접촉하는 구조에서
  이 전화가 가장 큰 잡무다.
- 비자 연장 트랙에서는 "다음 만료일과 그때 할 일"을 같은 화면으로 보여 줄 수 있어 재방문의 입구가 된다.

## 2. 무엇을 보여 주나

로그인 없이 문자로 받은 링크 하나로 연다. 한 화면, 위에서 아래로.

1. **어디쯤인가** — 트랙의 단계(결혼중개 6단계 또는 연장 5단계) 중 현재 위치. 지난 단계는 완료일, 현재
   단계는 시작일, 남은 단계는 예상 시기.
2. **다음에 할 일** — 타임라인 항목 중 손님이 직접 해야 하는 것만 골라서(아래 3-2). 마감일과 준비물.
3. **사무소가 하고 있는 일** — 나머지 항목의 제목만. 손님이 "누가 뭘 하는지"를 알면 불안이 준다.
4. **예상 일정** — 맞선일이 잡혔으면 실태조사 평균(맞선 → 혼인신고 4.8개월, 맞선 → 결혼식 9.3일)을 기준으로
   "대체로 ○월쯤"이라고만. 날짜를 단정하지 않는다(결혼중개업법 제12조).
5. **대표 연락** — 전화·카톡 버튼. 화면 안에서 바로 이어진다.
6. **바뀐 것** — 마지막 방문 이후 완료된 항목. 문자 없이도 진척이 보이게.

보여 주지 않는 것. 상대 분의 신상·사진, 다른 손님 정보, 캐럿·결제, 변호사 검토 내용, 규제 위반 경고.
손님 화면은 진척과 할 일만 담는다.

## 3. 데이터

### 3-1. 이미 있는 것
- `agencies/{aid}/clients/{cid}` — `currentStage`(1~6), `overallProgress`, `anchors`(고객 생성·계약·맞선·혼인신고·입국·체류만료).
- `agencies/{aid}/clients/{cid}/timeline/{itemId}` — 의무 항목 42종. `title`·`stage`·`dueDate`·`status`·`completedAt`.
- 트랙 정의 `src/domain/visaTracks.ts` — 단계 라벨·설명.

### 3-2. 더해야 하는 것
- **의무 템플릿에 `audience` 필드** — `'client' | 'agency' | 'both'`. 손님이 직접 하는 것(서류 제출·프로그램 이수·
  건강검진)과 사무소가 하는 것(등록증 확인·광고 심사·보험)을 가른다. 지금은 구분이 없어 42개를 다 보여 주면
  손님이 겁먹는다. 기본값은 `agency`로 두고 손님 몫만 명시한다.
- **공유 링크 문서** `agencies/{aid}/clients/{cid}/shareLinks/{token}`
  ```
  token        무작위 32자(base64url). 문서 ID로 쓴다.
  createdAt    발급 시각
  expiresAt    기본 90일. 연장 트랙은 다음 만료일 + 30일
  revokedAt    null. 대표가 끊으면 시각
  lastSeenAt   손님이 마지막으로 연 시각 (바뀐 것 계산용)
  createdBy    발급한 직원 uid
  ```
- **손님 화면용 읽기 전용 스냅샷** — 손님 화면은 Firestore 규칙을 우회할 수 없으므로 Cloud Function이
  토큰을 확인하고 필요한 필드만 추려 돌려준다. 원본 문서를 손님 브라우저에 그대로 보내지 않는다.

## 4. 경로와 함수

| 구성 | 내용 |
|---|---|
| 손님 화면 | `https://weddingcore.net/p/{token}` — 공개 라우트, noindex, 프리렌더 제외 |
| 조회 함수 | `getProgressByToken` (onRequest, App Check 없음). 토큰 → shareLinks 조회 → 만료·회수 확인 → 고객·타임라인 스냅샷 반환. `lastSeenAt` 갱신 |
| 발급 함수 | `issueProgressLink` (onCall, 업체 직원). 토큰 생성 + 문자 발송("진행 현황을 여기서 보실 수 있습니다 + 링크") |
| 회수 | 업체 화면 버튼 → `revokedAt` 기록. 같은 토큰은 즉시 무효 |
| 업체 화면 | 고객 상세(`/agency/clients/:id`)에 「손님에게 현황 링크 보내기」 버튼과 발급 이력 |

공개 라우트를 늘릴 때 손대는 네 곳(`docs/context-notes.md` 2026-08-29)을 그대로 따른다. 단 `/p`는
색인 대상이 아니므로 프리렌더·사이트맵에는 넣지 않고 워커 `ROUTE_PREFIXES`에만 넣는다.

## 5. 보안

- 토큰은 추측 불가 길이(32자 무작위)이고 URL 하나가 곧 열쇠다. 문자로만 보내고 화면 어디에도 목록으로
  노출하지 않는다. 문자는 손님 본인 번호(고객 문서의 `koreanClient.phone`)로만 간다.
- 만료·회수된 토큰은 404. "링크가 만료되었습니다. 사무소에 새 링크를 요청하세요"와 전화 버튼.
- 조회 함수는 IP당 분당 횟수 제한. 토큰을 무작위로 찔러 보는 시도를 막는다.
- 응답에는 손님 이름(성만), 단계, 손님 몫 항목, 마감일, 대표 연락처만. 상대 분 정보·주민번호·소득은 절대 넣지 않는다.
- 감사 로그. 발급·회수·조회 실패(만료 토큰 접근)를 `auditLogs`에 남긴다.

## 6. 문자

발급 시 1통. 이후 단계가 바뀔 때마다 1통(하루 최대 1통으로 묶는다).

```
[우리국제결혼중개사무소] 홍○○님 진행 현황
지금 단계: 서류 준비 (3/6)
다음 할 일: 소득금액증명원 제출 (9/20까지)
현황 보기: https://weddingcore.net/p/…
```

업체명은 업체 문서의 `name`. 손님 이름은 성 + ○○. 문자 발송은 기존 Solapi 경로(`consult/index.ts`의
`sendSms`, 받는 번호 지정)를 그대로 쓴다.

## 7. 비자 연장 트랙에서

- 단계는 연장 트랙 5단계(만료 확인 → 자격 점검 → 서류 준비 → 접수 → 허가).
- 「다음 만료일」과 「다음에 할 일」이 곧 재방문 안내다. 허가 완료 뒤에도 링크를 살려 두고 만료 90일 전에
  "다음 만료가 다가옵니다" 문자를 같은 링크로 보낸다.
- 영주(F-5)·간이귀화 자격 도달 시점(F-6로 2년)을 같은 화면 아래에 "다음 단계 안내"로 보여 준다.
  이것이 F-6 고객 생애주기 메모(`project_f6_client_lifecycle`)에서 말한 "졸업을 우리가 먼저 알려주는" 접점이다.

## 8. 구현 순서와 크기

| 순서 | 일 | 크기 |
|---|---|---|
| 1 | 의무 템플릿 42개에 `audience` 표시 (손님 몫 골라내기, 창희 변호사 확인) | 반나절 |
| 2 | `shareLinks` 스키마 + 규칙 + 발급·회수 함수 + 문자 | 1일 |
| 3 | 조회 함수 + 손님 화면 `/p/{token}` (모바일 우선, 밤 모드 토큰 재사용) | 1일 |
| 4 | 고객 상세 화면에 발급 버튼·이력 | 반나절 |
| 5 | 단계 변경 시 자동 문자(하루 1통 묶음) | 반나절 |
| 6 | 검증 — 만료·회수·무작위 토큰·모바일 화면, 실제 문자 1건 | 반나절 |

## 9. 열린 질문 (구현 전 결정)

- 손님 몫 항목의 마감일을 손님에게 그대로 보여 줄지, 며칠 앞당겨 보여 줄지. 업체가 여유를 두고 싶어 할 수 있다.
- 상대 분에게도 같은 화면(모국어)을 줄지. 나란히 보기 번역 자산이 있어 가능하지만, 상대 분의 연락처를 누가 관리하는지부터 정해야 한다.
- 우리결혼중개 홈페이지의 절차 페이지에서 "계약 손님은 여기서 현황을 봅니다" 안내 문구와 링크 자리.
