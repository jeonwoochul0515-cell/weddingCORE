# 03 · 고객 목록·등록 — 사장 시점 점검 (2026-09-05)

점검자 역할. 국제결혼중개업 사장. 휴대폰으로 손님 전화를 받고, 서류를 챙기고, 구청·출입국에 대응한다. 개발 용어를 모르고 화면 글자를 그대로 읽는다.
점검 범위. 「고객 관리」 화면의 고객 탭(목록), 「신규 고객」 등록 창, 등록 직후 넘어가는 고객 상세 첫 화면, 접수→고객 전환.
방법. 화면 코드를 끝까지 따라가 실제로 뜨는 글자와 버튼의 결과를 확인했다. 브라우저·실데이터는 쓰지 않았다. 추측인 곳은 "추측"이라고 적었다.

용어 한 줄 풀이(본문에서 쓰는 개발 용어).
- 타임라인 — 고객마다 자동으로 생기는 "법정의무 할 일 목록"(42개).
- 서버 함수 — 화면이 아니라 뒤쪽 컴퓨터에서 저절로 도는 처리. 사람이 누르지 않아도 실행된다.
- 보안 규칙(firestore.rules) — 누가 어떤 자료를 읽고 쓸 수 있는지 정해 둔 문서.
- 기준일(앵커) — 계약일·맞선일처럼 "그날부터 며칠"을 셀 때 기준이 되는 날짜.

## 발견

### 1. 목록의 "진행률 N%"가 영원히 0%다
- 심각도: 위험
- 어디서: 고객 관리 → 고객 탭 → 각 줄 오른쪽 "진행률 0%"
- 무슨 일이: 고객마다 "진행률 0%"라고 뜨는데, 이 숫자는 등록할 때 0으로 한 번 적히고 그 뒤로 아무도 고치지 않는다. 할 일을 20개 끝내도 목록은 계속 0%다. 반면 그 고객을 눌러 들어가면 타임라인 위에 "전체 진행률 47%"처럼 다른 숫자가 뜬다. 목록만 보고 "이 손님은 아직 하나도 안 했네"라고 판단하면 틀린다.
- 근거: 표시 `src/pages/ClientListPage.tsx:132` / 등록 때 0 저장 `src/features/agency/useAgencyClients.ts:95` / 이 값을 바꾸는 코드가 프로젝트 어디에도 없음(`overallProgress` 검색 결과가 위 두 곳과 자료 모양 정의 `src/types/schema.ts:270`뿐) / 상세 화면은 따로 계산 `src/features/timeline/TimelineView.tsx:57-61`
- 고칠 방향: 서버 함수(타임라인 항목이 바뀔 때 도는 `onTimelineItemUpdated`)에서 완료 비율을 고객 문서에 써 주거나, 목록에서 진행률을 빼고 "현재 단계 + 남은 할 일 수"만 보여준다.

### 2. "진행률"이 무엇의 진행률인지 화면 어디에도 없다
- 심각도: 말
- 어디서: 고객 목록의 "진행률 N%", 고객 상세의 "전체 진행률"
- 무슨 일이: 사장은 "결혼이 얼마나 진행됐나"로 읽는다. 실제로는 42개 법정의무 항목 중 "완료"로 체크한 개수의 비율이다. 맞선을 봤든 혼인신고를 했든, 체크를 안 하면 진행률은 오르지 않는다.
- 근거: 계산식이 완료 건수 ÷ 전체 건수 `src/features/timeline/TimelineView.tsx:57-61` / 목록 표기 `src/pages/ClientListPage.tsx:132` / 라벨에 설명 없음
- 고칠 방향: "법정의무 12/42 완료"처럼 무엇의 비율인지 글자로 보이게 한다.

### 3. 전화번호로 고객을 못 찾는다 — 검색은 이름·직업뿐
- 심각도: 답답
- 어디서: 고객 탭 검색창 "고객 이름 또는 직업으로 검색"
- 무슨 일이: 손님이 전화하면 휴대폰에 번호만 뜬다. 그 번호로 검색하면 아무것도 안 나온다. 검색은 이름과 직업 글자만 본다. 동명이인(김철수 셋)이면 직업으로 구별해야 한다. 검색 중에도 옆의 "진행 중 N명"은 전체 수 그대로라 "검색 결과 몇 명"을 알 수 없다.
- 근거: 안내문 `src/pages/ClientListPage.tsx:98` / 검색 대상이 `name`과 `occupation`만 `src/pages/ClientListPage.tsx:115` / 인원 수는 검색과 무관한 `items.length` `src/pages/ClientListPage.tsx:98`
- 고칠 방향: 검색 대상에 전화번호(하이픈 있든 없든)를 넣고, 안내문도 "이름·전화번호·직업"으로. 인원 수는 검색 결과 수로.

### 4. 단계별 필터도 정렬 선택도 없고, 순서가 저절로 바뀐다
- 심각도: 답답
- 어디서: 고객 탭 목록
- 무슨 일이: 30명, 100명이 되면 "비자 신청 단계인 사람만" 보고 싶은데 거를 방법이 없다. 순서는 "최근에 뭔가 바뀐 사람"이 위로 오는 한 가지뿐이고 바꿀 수 없다. 프로필 저장·기준일 기록·단계 넘어감이 생길 때마다 그 고객이 맨 위로 튀어 올라와서 어제 봤던 자리에 그 손님이 없다. 등록일·담당자·다음 마감일 같은 정보도 목록에 없다. 대시보드는 "맞선 단계 4명, 비자 단계 2명"이라고 세어 주면서 그 카드를 눌러도 아무 데도 안 간다.
- 근거: 조회 조건이 "진행 중 + 최근 변경순" 한 가지 `src/features/agency/useAgencyClients.ts:29-33` / 정렬·필터 UI 없음 `src/pages/ClientListPage.tsx:97-136` / 순서를 바꾸는 갱신들 — 프로필 저장 `src/features/matching/useClientProfile.ts:13`, 기준일 기록 `functions/src/timeline/index.ts:229-232`, 단계 넘어감 `functions/src/timeline/index.ts:190-193` / 대시보드 "진행 중 고객" 카드에 링크 없음(접수 카드는 있음) `src/pages/AgencyDashboardPage.tsx:114` vs `128-137`
- 고칠 방향: 단계 칩(계약 전/계약 체결/…) 필터, 이름순·등록순·마감 임박순 정렬, 줄에 등록일·다음 마감을 추가. 대시보드 단계 수는 눌러서 그 단계 목록으로.

### 5. 목록에 전화번호가 없고, 어디서도 바로 전화를 못 건다
- 심각도: 답답
- 어디서: 고객 탭 각 줄, 고객 상세 "연락처"
- 무슨 일이: 접수 탭은 줄마다 번호가 보이고 펼치면 "010-…로 전화" 버튼이 있어 휴대폰에서 바로 걸린다. 그런데 고객으로 등록하는 순간 그게 사라진다. 고객 목록 줄에는 번호가 없고, 상세에 들어가도 번호가 글자로만 적혀 있어 눌러도 걸리지 않는다. 손님 전화에 답하려면 번호를 외워 쓰거나 복사해야 한다.
- 근거: 목록 줄 구성(이름·성별·직업·단계·진행률뿐) `src/pages/ClientListPage.tsx:121-133` / 상세는 글자만 `src/pages/ClientDetailPage.tsx:96` / 접수 탭은 전화 버튼 있음 `src/features/leads/LeadsPanel.tsx:130,194`
- 고칠 방향: 목록 줄에 번호 + 전화 아이콘(`tel:` 링크), 상세 연락처도 눌러서 걸리게.

### 6. 같은 사람을 두 번 등록해도 아무 말이 없다
- 심각도: 위험
- 어디서: 신규 고객 등록 창 → 등록
- 무슨 일이: 직원 둘이 같은 손님을 각각 등록하거나, 사장이 지난달 등록한 걸 잊고 다시 등록하면 그대로 두 명이 생긴다. 이름·전화번호가 똑같아도 확인 문구가 없다. 고객마다 타임라인 42개가 자동으로 붙으니, 중복 고객은 곧 "가짜 기한·가짜 경고" 42개다. 전화번호는 적은 그대로 저장되어 "010-1234-5678"과 "01012345678"이 다른 번호로 취급된다.
- 근거: 무조건 새 문서 생성 `src/features/agency/useAgencyClients.ts:77` / 번호 정리 없이 그대로 저장 `src/features/agency/useAgencyClients.ts:87` / 중복 검사 코드 없음(`중복`·`duplicate`·`already` 검색 결과 없음) / 고객마다 타임라인 자동 생성 `functions/src/timeline/index.ts:46-108`
- 고칠 방향: 등록 직전에 같은 전화번호(숫자만 비교)가 있으면 "이미 ○○○님(계약 체결 단계)이 있습니다. 그 고객으로 갈까요?"를 띄운다.

### 7. 접수→고객 전환이 반쯤 실패하면, 다시 누를 때 고객이 한 명 더 생긴다
- 심각도: 위험
- 어디서: 접수 탭 → 펼치기 → "고객으로 등록" → 등록
- 무슨 일이: 이 버튼은 두 단계로 움직인다. ① 고객을 만들고 ② 접수 카드를 "고객 등록"으로 바꾼다. ②가 실패하면(전파가 약하거나 잠깐 끊긴 경우) 화면은 아무 말 없이 고객 상세로 넘어가고, 접수 카드는 "상담 중" 그대로 남아 "고객으로 등록" 버튼이 계속 보인다. 코드 주석은 "목록에서 다시 누르면 된다"고 적어 두었는데, 다시 누르면 등록 창이 또 열려 ①을 또 하기 때문에 같은 사람이 두 명이 된다. 사장은 실패한 줄도 모른다.
- 근거: ①고객 생성 뒤 ②접수 갱신, 실패는 조용히 삼킴 `src/pages/ClientListPage.tsx:152-163` (주석 `:159`) / "고객으로 등록" 버튼은 상태가 전화했음·상담 중이면 계속 표시 `src/features/leads/LeadsPanel.tsx:191-201` / 다시 누르면 새 등록 창 `src/pages/ClientListPage.tsx:147-150` → 새 고객 생성 `src/features/agency/useAgencyClients.ts:77`
- 고칠 방향: ②가 실패하면 "고객은 만들어졌지만 접수 표시를 못 바꿨습니다. 다시 시도" 문구를 띄우고, 접수에 `clientId`가 이미 있거나 같은 번호의 고객이 있으면 등록 창 대신 그 고객으로 이동.

### 8. 등록이 안 될 때 영어 문장이 뜨거나, 아예 아무 반응이 없다
- 심각도: 말
- 어디서: 신규 고객 등록 창 → 등록
- 무슨 일이: (같은 계열의 다른 사례 — 로그인 오류 영어 문구는 이미 보고됨.) 열람 전용 직원(readonly)이 등록을 누르면 보안 규칙이 막고, 화면에는 "Missing or insufficient permissions." 같은 영어 원문이 그대로 뜬다. 또 로그인 정보에 업체 ID가 아직 안 붙은 상태에서는 등록 버튼을 눌러도 창이 그대로 있고 아무 문구도 없다. "신규 고객" 버튼은 권한과 상관없이 모두에게 보인다.
- 근거: 업체 ID 없으면 조용히 중단 `src/features/agency/CreateClientDialog.tsx:40` / 오류 원문을 그대로 표시 `src/features/agency/CreateClientDialog.tsx:51,107` / 쓰기 권한은 owner·manager·staff만 `firestore.rules:14-16`, 고객 생성 규칙 `firestore.rules:137-139` / 버튼은 누구에게나 `src/pages/ClientListPage.tsx:70-72`
- 고칠 방향: 권한 없는 역할에는 버튼을 숨기거나 "열람 전용 계정은 등록할 수 없습니다"로. 오류는 우리말 한 줄("저장하지 못했습니다. 잠시 후 다시 시도해 주세요")로 바꾸고 원문은 접어 둔다.

### 9. 성별 "남"·혼인이력 "미혼"이 처음부터 골라져 있다 — 여성·이혼 고객이 조용히 잘못 저장된다
- 심각도: 위험
- 어디서: 신규 고객 등록 창의 성별·혼인이력 칸
- 무슨 일이: 창을 열면 성별은 "남", 혼인이력은 "미혼"으로 이미 선택돼 있다. 바쁜 현장에서 이름·전화·주소를 치고 등록을 누르면 여성 고객이 "남"으로, 재혼 고객이 "미혼"으로 저장된다. 이 두 값은 나중에 고칠 수 없고(기본정보 수정 불가 — 이미 보고됨), 혼인이력은 법정 신상정보 항목(BG_KOR_MARITAL_HISTORY)으로 이어진다. 접수에서 넘어온 경우엔 혼인이력을 못 읽으면 비워 두려는 의도가 코드에 있지만, 기본값 "미혼"이 그 자리를 채워 버린다.
- 근거: 기본값 지정 `src/features/agency/CreateClientDialog.tsx:35` / 접수에서 못 읽으면 비우려는 의도 `src/pages/ClientListPage.tsx:23-32` (그러나 `undefined`는 기본값 `none`을 덮지 못함, `CreateClientDialog.tsx:35` 전개 순서) / 여성 고객 표시 자체는 "여"로 문제 없음 `src/pages/ClientListPage.tsx:124`, `src/pages/ClientDetailPage.tsx:89`
- 고칠 방향: 두 칸 모두 "선택하세요"에서 시작하고 필수로 막는다.

## 확신이 낮은 항목
- **휴대폰에서 등록 창의 "등록" 버튼이 하단 메뉴에 가려질 수 있다 (추측).** 등록 창은 화면 겹침 순서(z-index) 30, 휴대폰 하단 메뉴는 40이라 메뉴가 창 위에 그려진다. 창 높이가 화면의 92%까지 늘어나므로 작은 폰에서는 맨 아래 "취소·등록" 줄이 메뉴 뒤로 들어갈 수 있다. 실제 기기로 확인해야 한다. 근거: `src/features/agency/CreateClientDialog.tsx:56-57`, `src/components/layout/Sidebar.tsx:60`.
- **연소득에 음수를 넣으면 아무 말 없이 등록이 안 된다 (추측).** 최소값 0 규칙에 문구가 없어 오류 글자가 빈 문자열이 되고, 빈 문자열은 화면에 표시되지 않는다. 등록 버튼을 눌러도 창이 그대로다. 근거: `src/features/agency/CreateClientDialog.tsx:96,135`. 실제 동작은 폼 라이브러리(react-hook-form) 버전에 따라 다를 수 있다.
- **13번의 "몇 초"는 추측이다.** 서버 함수가 잠들어 있다가 깨는 시간은 실측하지 않았다.
