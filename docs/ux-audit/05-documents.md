# 05 · 서류·일관성 — 사장 시점 점검 (2026-09-05)

점검자 설정. 국제결혼중개업소 사장. 휴대폰으로 손님 서류를 사진 찍어 올리고, 화면에 뜬 글자를 그대로 읽는다. 개발 용어는 모른다.

용어 풀이(이 문서에서 쓰는 말).
- 저장소(Storage) — 올린 파일(사진·PDF)이 실제로 놓이는 창고.
- 저장 규칙(rules) — 그 창고에 "누가·어떤 파일을·얼마 크기까지" 넣을 수 있는지 정한 문지기 규칙.
- 서류 기록(Firestore documents) — 파일 자체가 아니라 "이 파일은 무슨 서류이고 발급일·만료일이 언제"라는 꼬리표.
- 앵커(기준일) — 맞선 예정일·혼인신고일처럼 다른 기한을 계산하는 기준이 되는 날짜.

## 발견

### 1. 업로드가 저장 규칙에 걸려 아예 안 올라갈 가능성이 크다
- 심각도: 막힘
- 어디서: 고객 상세 → 컴플라이언스 탭 → 서류 → [업로드] → 파일 고르고 [업로드]
- 무슨 일이: 파일을 넣는 주소는 `…/documents/파일이름` 한 칸인데, 저장 규칙은 `…/documents/{docId}/{file}` 두 칸짜리 주소에만 허가를 준다. 규칙에 맞는 줄이 없으면 창고는 기본으로 거절한다. 사장은 [업로드]를 누른 뒤 빨간 영어 한 줄만 보게 된다(다음 항목). 이 규칙 파일이 실제로 배포된 그대로라면, 서류 기능 전체가 처음부터 안 되는 셈이다.
- 근거: `src/features/documents/useClientDocuments.ts:54-59`(주소 `documents/${fileKey}`), `storage.rules:15`(`documents/{docId}/{file}`), `firebase.json`의 `"storage": {"rules": "storage.rules"}`. 작업 노트(`docs/checklist.md`, `docs/context-notes.md`)에 서류 업로드를 실제로 눌러 본 기록은 없다.
- 고칠 방향: 규칙을 `documents/{file}`로 맞추거나(단순), 파일 주소에 꼬리표 id를 넣는 순서로 바꾼다. 고친 뒤 휴대폰에서 실제로 한 장 올려 확인한다.

### 2. 실패하면 영어 원문 오류가 그대로 뜨고, 용량·형식 제한은 어디에도 안 적혀 있다
- 심각도: 말 (실패 원인이 규칙이면 막힘)
- 어디서: 업로드 창 아래 빨간 글
- 무슨 일이: 오류는 시스템이 준 메시지를 그대로 보여 준다. 규칙에 걸리면 "Firebase Storage: User does not have permission to access '…'. (storage/unauthorized)" 같은 영어가 뜬다. 20MB를 넘겨도, PDF·사진이 아닌 파일(예: 한글 .hwp, .zip)을 골라도, 읽기 전용 직원이 올려도 전부 같은 영어 문장이다. 창 어디에도 "20MB까지, 사진 또는 PDF"라는 안내가 없다.
- 근거: `src/features/documents/DocumentSection.tsx:143-144`(`setError((err as Error).message)`), `:186`(그대로 표시), `:184`(파일 고르기만 `image/*,pdf`로 제한, 용량 확인 없음). 제한 자체는 `storage.rules:18-22`(20MB, image/pdf, owner·manager·staff만). `firestore.rules:9-12`에서 `readonly` 역할은 볼 수 있지만 `storage.rules:20`에서 올리기는 막힌다.
- 고칠 방향: 누르기 전에 용량·형식을 검사해 "사진 또는 PDF, 20MB까지 올릴 수 있어요"를 창에 적고, 오류는 우리말 세 가지(너무 큼 / 형식 아님 / 권한 없음)로 바꿔 보여 준다.

### 3. 범죄경력·건강진단서 기본 유효기간 6개월이 비자 접수 기준보다 느슨하다
- 심각도: 위험
- 어디서: 서류 목록의 초록 `D-○○` 배지, 서류 점검 카드
- 무슨 일이: 발급일만 넣으면 범죄경력증명서·건강진단서는 6개월 뒤를 만료일로 잡는다. 그런데 재외공관의 결혼이민(F-6) 안내는 제출 서류를 "신청일 기준 3개월 이내 발급"으로 요구한다. 발급 4개월 된 범죄경력증명서가 화면에서는 초록 `D-60`으로 보이는데, 공관에 내면 반려될 수 있다. 앱 안의 타임라인 설명문도 "범죄경력·건강진단 6개월"이라 적어 같은 기준을 쓰고 있어, 화면과 안내문이 서로는 맞고 바깥 기준과만 어긋난다.
- 근거: `src/features/documents/types.ts:21-29`(criminal_record 6, health_cert 6, marital_cert 3, income_proof 3), `functions/src/admin/obligationTemplates.ts:620-621`("범죄경력·건강진단 6개월"), `:390`("통상 6개월 이내 발급본만 유효"). 바깥 기준은 외교부 공관 안내(주남아공 대사관 "결혼이민(F-6) 비자 신청 안내" — 모든 서류 신청일 기준 3개월 이내 발급; 주미국 대사관 2023-04-13 안내). 결혼중개업법 쪽(신상정보 제공용) 기준과 출입국 쪽(비자 접수용) 기준이 다를 수 있으니 변호사 확인 필요.
- 고칠 방향: 용도(신상정보 제공 vs 비자 접수)별로 기준을 나누거나, 보수적으로 3개월로 낮추고 근거를 화면에 적는다.

### 4. 발급일을 안 넣거나 여권·기타를 올리면 "유효기간 없음"이 초록으로 뜬다
- 심각도: 위험
- 어디서: 서류 목록 오른쪽 배지
- 무슨 일이: 발급일 칸은 선택이라 건너뛰기 쉽다. 건너뛰면 만료일이 안 잡히고 배지가 초록색 "유효기간 없음"이 된다. 여권과 기타는 기본값 자체가 없어서 여권 만료일을 손으로 넣지 않으면 영영 초록이다. 사장은 초록을 "괜찮다"로 읽는다. 업로드 창의 "미입력 시 서류 유형별 기본값 적용" 글은 그 기본값이 몇 개월인지 어디에도 안 보여 준다.
- 근거: `src/features/documents/types.ts:49`(만료일 없으면 `level: 'ok'`, "유효기간 없음"), `src/features/documents/DocumentSection.tsx:19-23`(ok = 초록), `:174`·`:178`(안내 문구), `types.ts:21-29`(passport·other 기본값 없음).
- 고칠 방향: 만료일 없는 서류는 회색 "만료일 모름"으로 바꾸고, 여권을 고르면 "여권 만료일을 넣어 주세요"를 붉게 띄운다. 종류를 고르면 "기본 6개월(2027-03-05까지)"처럼 계산 결과를 바로 보여 준다.

### 5. 같은 서류를 새로 올려도 옛것이 그대로 남고, 옛 서류의 빨간 경고가 매일 되살아난다
- 심각도: 위험
- 어디서: 서류 목록, 서류 점검 카드, 알림 종
- 무슨 일이: 만료된 범죄경력증명서를 새로 발급받아 올리면 목록에 둘 다 남는다. "이게 최신"이라는 표시가 없고, 꼬리표의 `replaces`(무엇을 대체하는지) 칸은 항상 비워서 저장한다. 점검 카드는 옛 서류를 보고 "범죄경력증명서 유효기간이 지났습니다"를 계속 붉게 띄우고, 서버는 매일 아침 9시에 그 옛 서류로 알림을 하나 더 만든다. 지울 수도 없으니(기발견) 사장은 없앨 방법이 없는 빨간 경고를 안고 산다.
- 근거: `src/features/documents/useClientDocuments.ts:82`(`replaces: null` 고정), `src/features/documents/consistency.ts:119-139`(모든 서류를 돌며 만료 경고), `functions/src/documents/index.ts:33-36`(만료 30일 이내·이미 만료된 서류 전부), `:82-95`(서류마다 날짜별 알림 생성).
- 고칠 방향: 같은 종류·같은 대상을 다시 올리면 "이전 서류를 대체할까요?"를 묻고 `replaces`를 채운다. 대체된 서류는 점검·알림에서 뺀다.

### 6. 종류·대상·날짜를 잘못 고르고 올리면 고칠 수 없다 (기본값이 범죄경력증명서·한국인 측)

### 7. "신상정보 교환" 화면에서 다 해 놓아도 점검 카드는 "신상정보 서류가 없습니다 … 형사 벌칙"이라고 빨갛게 말한다

## 확신이 낮은 항목

- **아이폰 HEIC 사진.** 사진첩에서 고르면 iOS가 보통 JPEG로 바꿔 주지만, "파일" 앱에서 고르면 HEIC 그대로 올라갈 수 있다. 저장 규칙은 `image/.*`라 통과시키고(`storage.rules:22`), 그러면 윈도우·안드로이드 크롬에서 "열기"를 눌렀을 때 화면에 안 뜨고 내려받기만 될 수 있다. 추측이며 실기기 확인 필요.
- **사진 회전.** 별도 처리는 없다. 요즘 브라우저는 사진 안의 회전 정보를 읽어 바로 세워 보여 주므로 대개 괜찮을 것으로 본다. 추측.
- **형식을 알 수 없는 파일.** 일부 안드로이드 파일 앱은 형식 정보를 비워 보낸다. 그러면 저장 규칙의 형식 검사(`storage.rules:22`)에 걸려 영어 오류가 뜬다. 추측.
- **월말 발급일 계산.** 8월 31일 발급 + 6개월은 "2월 31일"이 없어 3월 3일로 밀린다(`src/features/documents/types.ts:34-36`의 `setMonth`). 며칠 차이라 실무 영향은 작다.
- **파일만 올라가고 꼬리표가 안 남는 경우.** 파일 저장 뒤 꼬리표 저장이 실패하면(연결 끊김 등) 창고에는 파일이 남고 목록에는 안 보인다. 다시 올리면 파일이 둘이 된다(`src/features/documents/useClientDocuments.ts:59-84`). 실제 빈도는 추측.
- **점검 카드 같은 제목 겹침.** 만료된 같은 종류 서류가 둘이면 제목이 같은 항목이 둘 생겨(`src/features/documents/ConsistencyCard.tsx:49`, `key={issue.title}`) 화면 갱신이 어긋날 수 있다. 개발 경고 수준.
- **3번 항목의 바깥 기준.** 공관 안내(신청일 기준 3개월)는 웹 검색으로 확인한 것이며 공관·시기마다 문구가 다를 수 있다. 변호사 확인 뒤 기본값을 정하는 것이 맞다.
