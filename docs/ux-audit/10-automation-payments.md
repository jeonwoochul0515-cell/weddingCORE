# 10 · AI 자동화·캐럿·결제 — 사장 시점 점검 (2026-09-05)

점검자 역할. 국제결혼중개업 사장. 휴대폰으로 화면을 보고, 개발 용어를 모르고, 화면 글자를 그대로 읽는다.
점검 방법. 화면 코드와 서버 코드, 저장 규칙을 끝까지 따라가며 "버튼을 누르면 실제로 무엇이 되는지"를 확인했다. 브라우저·개발 서버·실데이터는 쓰지 않았다.

## 발견

### 1. 계좌이체로 신청하면 "안내되는 계좌"가 어디에도 없다
- 심각도: 막힘
- 어디서: AI 업무 자동화 → 캐럿 충전 → 「계좌이체로 신청」
- 무슨 일이: 신청을 누르면 "110캐럿 충전을 신청했습니다. 입금이 확인되면 캐럿이 지급됩니다."라고만 뜬다. 화면 아래에는 "신청 후 안내되는 계좌로 입금하면 확인 즉시 캐럿이 지급됩니다."라고 적혀 있는데, 계좌번호·은행·입금자명·입금 기한이 화면·문자·알림 어디에도 나오지 않는다. 코드 전체에 계좌번호가 없다. 관리자 쪽에도 신청 목록을 보거나 지급 버튼을 누르는 화면이 없어서, 서버에 있는 지급 함수(`grantAiCarats`)를 부르는 화면이 하나도 없다. 사장은 신청만 하고 기다리다 끝난다. (신청 자체가 저장 규칙 packId 불일치로 거부되는 것은 이미 보고됨. 그때 뜨는 문구도 "신청하지 못했습니다: Missing or insufficient permissions."로 영어다.)
- 근거: `src/pages/AutomationCenterPage.tsx:82-85`(신청 완료 문구), `:200-202`("안내되는 계좌" 문구), `:87`(영어 오류 그대로 표시). 계좌번호 검색 결과 없음(`src`, `functions/src` 전체). `src/pages/AdminAgenciesPage.tsx` 141줄 전체에 충전·주문 관련 코드 없음. `functions/src/automation/index.ts:479-538`(지급 함수는 있음), `src` 안에 `grantAiCarats` 호출 없음.
- 고칠 방향: 신청 직후 화면과 문자로 은행·계좌·금액·입금자명 표기 방법을 보여 주고, 관리자 화면에 "입금 확인 → 지급" 버튼을 붙인다. 계좌이체를 당장 못 받으면 버튼을 빼는 편이 낫다.

### 2. 만든 초안을 인쇄·복사·내려받을 방법이 없다
- 심각도: 막힘
- 어디서: AI 업무 자동화 → 최근 자동화 작업 → 항목 펼침
- 무슨 일이: 초안 본문이 글상자(`pre` 태그. 글을 있는 그대로 보여 주는 칸) 안에만 있다. 인쇄 버튼, 복사 버튼, 파일로 저장 버튼이 없다. 변호사 승인이 끝난 문서도 마찬가지라, 사장은 휴대폰에서 긴 글을 손가락으로 끌어 선택해 복사해야 한다. 같은 서비스의 매칭 리포트와 비자 시뮬레이터에는 인쇄 버튼이 있다.
- 근거: `src/pages/AutomationCenterPage.tsx:283`(pre 태그만), 파일 전체에 `print`·`clipboard`·`download` 없음. 비교: `src/features/matching/MatchReport.tsx:53`(window.print), `src/features/visaSimulator/ResultView.tsx:106`(인쇄 버튼).
- 고칠 방향: 승인된 초안에 「복사」「인쇄/PDF 저장」 버튼을 붙인다. 승인 전에는 "초안" 워터마크를 넣어 인쇄한다.

### 3. 변호사가 "수정 요청"을 하면 사장이 할 수 있는 일이 없다
- 심각도: 막힘
- 어디서: 최근 자동화 작업 → 상태 「수정 요청」
- 무슨 일이: 변호사가 수정 요청을 남기면 사장 화면에는 "검토 의견: …"만 뜨고 끝이다. 고쳐서 다시 올리는 버튼도, 같은 문서를 다시 만드는 버튼도 없다. 문서 버전은 항상 1이다. 다시 만들려면 처음부터 새로 생성해야 하고 캐럿(110캐럿=11만원)이 전액 다시 빠진다. 새 초안은 이전 것과 연결되지 않아 변호사도 무엇이 바뀌었는지 모른다.
- 근거: `src/pages/AutomationCenterPage.tsx:281`(검토 의견 표시뿐), `functions/src/automation/index.ts:279`(version 1 고정), `:258-259`(생성마다 전액 차감), `:430-432`(검토 함수는 '검토 대기' 상태만 처리).
- 고칠 방향: 수정 요청 상태에 「의견 반영해 다시 만들기」 버튼을 두고, 같은 작업의 버전을 올리며 재생성 비용은 할인하거나 무료로 한다.

### 4. 변호사 검토가 며칠 걸리는지, 끝났는지 알려 주지 않는다
- 심각도: 답답
- 어디서: 초안 생성 직후 안내 문구, 알림 종
- 무슨 일이: 생성하면 "초안을 생성해 변호사 검토 큐로 보냈습니다."라고 뜬다. "큐"는 개발 용어(대기 줄)다. 며칠 걸리는지 안내가 없다. 변호사가 승인하거나 수정 요청을 해도 알림이 오지 않는다. 알림 종에 들어오는 종류는 서류 만료·기한·법령 개정·위반 네 가지뿐이고, 검토 결과나 캐럿 지급은 없다. 사장은 자동화 화면을 수시로 열어 확인해야 한다.
- 근거: `src/pages/AutomationCenterPage.tsx:119`(큐 문구), `functions/src/automation/index.ts:448-462`(검토 처리 시 알림 문서를 만들지 않음), `src/features/regulatoryRadar/useAgencyNotifications.ts:14`(알림 종류 4개), 서버에서 알림을 만드는 곳은 `functions/src/documents/index.ts:84`·`functions/src/regulations/index.ts:151` 둘뿐. 문서(`docs/*.md`)에도 검토 기간 약속 없음.
- 고칠 방향: 생성 직후 "보통 N영업일 안에 검토합니다"를 보여 주고, 승인·수정 요청·캐럿 지급 때 알림과 문자를 보낸다.

### 5. 생성이 70초를 넘기면 사장 화면엔 실패로 뜨는데 캐럿은 빠지고 초안은 만들어진다
- 심각도: 위험
- 어디서: 「N캐럿으로 초안 생성」 버튼
- 무슨 일이: 화면은 서버 응답을 최대 70초만 기다린다(설정을 따로 안 해서 기본값). 서버는 최대 180초까지 AI 생성을 계속한다. AI가 긴 문서를 쓰느라 70초를 넘기면 사장 화면에는 빨간 상자에 "deadline-exceeded"라는 영어만 뜬다. 그 사이 서버는 초안을 완성해 목록에 올리고 캐럿을 차감한다. 사장이 실패한 줄 알고 다시 누르면 같은 문서가 두 번 만들어지고 캐럿이 두 번 빠진다.
- 근거: `src/pages/AutomationCenterPage.tsx:117`(대기시간 옵션 없음), `node_modules/@firebase/functions/dist/index.cjs.js:617`(기본 70000ms), `:429`(초과 시 'deadline-exceeded' 문자열), `functions/src/automation/index.ts:233`(서버 180초), `:205`(최대 5,000토큰 생성). 실제로 70초를 넘기는 빈도는 확인 못 함(추측).
- 고칠 방향: 화면 대기시간을 서버와 맞추거나(180초), 버튼을 누르면 즉시 "생성 중" 항목을 목록에 넣고 화면은 기다리지 않게 바꾼다. 영어 오류는 "시간이 오래 걸리고 있습니다. 목록을 확인해 주세요."로 바꾼다.

### 6. 생성 실패 시 캐럿은 자동으로 돌아오는데 화면은 "관리자에게 문의하라"고 한다. 돌려주는 계산도 어긋난다
- 심각도: 위험
- 어디서: 최근 자동화 작업 → 상태 「생성 실패」
- 무슨 일이: 실패한 작업을 펼치면 "검토 의견: AI 문서 생성에 실패했습니다. 캐럿 복구는 관리자에게 문의해 주세요."라고 뜬다. 그런데 서버는 바로 다음 줄에서 캐럿을 자동으로 되돌린다. 사장은 안 돌아온 줄 알고 문의하게 된다. 게다가 이 문장이 "검토 의견"이라는 제목 아래 뜨니 변호사가 쓴 말처럼 읽힌다. 돌려주는 계산도 "이 작업이 어디서 뺐는지"가 아니라 "무료분부터" 돌려준다. 예를 들어 이번 달 무료 20캐럿을 이미 다 쓴 뒤 110캐럿 문서를 만들다 실패하면(전액 충전분에서 차감), 복구 때 무료분 사용량을 20→0으로 되돌리고 충전분에는 90만 돌려준다. 돈 주고 산 20캐럿이 월말에 사라지는 무료 20캐럿으로 바뀐다.
- 근거: `functions/src/automation/index.ts:347-352`(문구 저장 직후 `restoreCredits` 호출), `:108-123`(복구는 `min(cost, used)`를 무료분에 먼저), `:95-100`(차감은 무료분 먼저, 모자란 만큼 충전분), `src/pages/AutomationCenterPage.tsx:281`("검토 의견:" 제목으로 표시).
- 고칠 방향: 실패 문구를 "캐럿은 자동으로 돌려드렸습니다"로 바꾸고 "검토 의견" 제목과 분리한다. 차감 때 무료분·충전분 각각 몇 캐럿을 뺐는지 작업 문서에 적어 두고, 복구는 그 숫자대로 되돌린다.

### 7. 캐럿이 모자라면 생성 버튼이 그냥 회색이 되고 이유를 말해 주지 않는다
- 심각도: 답답
- 어디서: 「N캐럿으로 초안 생성」 버튼
- 무슨 일이: 잔여 캐럿이 문서 비용보다 적으면 버튼이 눌리지 않는데, 왜 안 눌리는지 문구가 없다. 버튼 아래엔 "AI 결과는 법률의견이 아니며…"라는 다른 얘기만 있다. 월 무료 20캐럿으로는 110캐럿짜리 패키지를 못 만드니, 가입 첫날 F-6 패키지를 고른 사장은 회색 버튼만 보게 된다. 고객을 안 골랐을 때, 동의를 안 했을 때도 같은 회색이라 원인을 구분할 수 없다.
- 근거: `src/pages/AutomationCenterPage.tsx:263`(잠금 조건 네 가지가 한 줄에 묶임, 안내 없음), `:264`(버튼 아래 문구), `pricing.md:74-76`("월 무료 20캐럿으로는 서류 한 건만 된다"고 스스로 적어 둠).
- 고칠 방향: 잠긴 이유를 버튼 위에 한 줄로 보여 준다. "캐럿이 90 부족합니다 → 충전하기" 처럼 다음 행동으로 이어지는 링크를 붙인다.

### 8. "이번 달 AI 캐럿" 숫자는 무료+충전 합계인데 제목은 "이번 달"이고 원 환산이 없다
- 심각도: 말
- 어디서: 자동화 화면 상단 오른쪽 카드
- 무슨 일이: 큰 숫자는 무료 잔여와 충전분을 합친 값인데 제목이 "이번 달 AI 캐럿"이라 "이번 달에 쓸 수 있는 무료분"으로 읽힌다. 바로 아래 초록 게이지는 무료분만 반영해 숫자와 게이지가 따로 논다. "1캐럿 = 1,000원"은 10px 글씨다. 문서 고르는 칸과 생성 버튼에는 원이 붙어 있는데(예: 110캐럿(110,000원)) 잔액에만 원이 없어서, 사장은 "130캐럿"이 13만원어치인지 매번 계산해야 한다.
- 근거: `src/pages/AutomationCenterPage.tsx:138-142`(제목·숫자·게이지·10px 안내), `:62-64`(합계 계산), `:241`·`:263`(문서·버튼은 원 표기).

### 9. 월 무료 캐럿이 몇 개인지는 서버 설정값이고, 사장에게는 이 화면 말고는 알려 주지 않는다

- **5번의 빈도.** 70초 초과가 얼마나 자주 나는지는 실측하지 않았다. 최대 5,000토큰 생성이라 긴 패키지 문서에서 넘길 가능성은 있다(추측).
- **캐럿 정보가 없는 업체.** 업체 문서에 `aiCredits`가 없으면 화면은 무료분을 0으로 보여 버튼이 잠기는데(`src/pages/AutomationCenterPage.tsx:56`), 서버는 기본 20을 준다(`functions/src/automation/index.ts:82`). 가입 흐름은 `selfProvisionAgency`가 값을 넣으므로(`src/pages/AgencySignupPage.tsx:235`, `functions/src/index.ts:55-59`) 정상 가입 업체에는 안 생길 수 있다. 시험 계정이나 관리자가 수동으로 만든 업체에서만 날 수 있다(추측).
- **카드 버튼이 켜져 있는데 서버 시크릿이 자리표시 값인 경우.** 화면은 클라이언트 키만 보고 버튼을 켠다(`src/features/payments/useCheckout.ts:20`, `.env.local`에 키 있음). 서버 시크릿이 `NOT_CONFIGURED`면 누른 뒤에야 "카드 결제가 아직 열리지 않았습니다"가 뜬다(`functions/src/payments/toss.ts:67-73`). `docs/payments-setup.md`는 자리표시 값이라 하고 전역 메모(2026-08-31)는 설정됐다고 한다. 실데이터를 보지 않아 현재 상태는 모른다.
- **토스 승인은 됐는데 우리 기록이 실패한 경우.** 승인 요청 성공 뒤 저장 단계(`functions/src/payments/toss.ts:207-228`)에서 오류가 나면 카드값은 나갔는데 캐럿이 안 오고, 결과 화면은 "승인되지 않은 건은 자동으로 취소됩니다"(`src/pages/PaymentResultPage.tsx:111-112`)라고 안내한다. 웹훅(토스가 우리 서버에 결과를 알려 주는 장치)이 없어 자동으로 바로잡히지 않는다. 드문 경우라 빈도는 모른다(추측).
