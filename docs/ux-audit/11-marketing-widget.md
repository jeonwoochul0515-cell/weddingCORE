# 11 · 마케팅·위젯·빠른 점검 — 사장 시점 점검 (2026-09-05)

점검자 역할. 국제결혼중개업 사장. 개발자가 아니고 휴대폰을 더 자주 쓴다. 홈페이지는 몇 년 전 외주 업체가 만들어 줬거나 네이버 모두·카페24로 직접 만든 상태다. "홈페이지에 점검 위젯을 넣으라"는 말을 듣고 마케팅 센터에 들어와 본다. 손님이 홈페이지에서 점검을 하고 연락처를 남기면 어떻게 되는지까지 따라갔다.

이미 다른 점검자가 찾은 항목(검색 준비도 고정값, AEO·GEO 같은 영어 용어, 영어 소제목, 연소득 필수 등)은 다시 적지 않았다. 같은 계열의 **다른** 사례만 적었다.

용어 한 줄. **iframe(아이프레임)** = 남의 사이트 화면을 내 홈페이지 안에 창문처럼 끼워 넣는 방식. **삽입 코드** = 그 창문을 만드는 글자 몇 줄. **URL 값(주소 뒤 값)** = 주소 끝에 `?agency=…&name=…`처럼 붙는 글자로, 누구나 바꿔 쓸 수 있다.

## 발견

### 1. 마케팅 상담 요청을 보내면 아무에게도 알려지지 않고, 보낸 뒤 볼 화면도 없다
- 심각도: 막힘
- 어디서: 마케팅 센터 → "마케팅 상담 요청" → 「상담 요청 접수」 버튼
- 무슨 일이: 버튼을 누르면 "마케팅 상담 요청이 접수되었습니다"라고 뜨고 끝이다. 이 요청을 읽는 화면이 사장 쪽에도, 관리자 쪽에도 없고, 문자나 메일도 안 나간다. 저장소에 문서 하나가 조용히 쌓일 뿐이다. 맨 위 큰 글씨는 "한곳에서 신청하고 진행상황을 관리하세요"라고 하는데 진행상황을 볼 곳이 없다. 사장은 "연락이 왜 안 오지" 하며 또 보내게 되고, 그것도 아무도 모른다.
- 근거: 저장은 `src/pages/MarketingCenterPage.tsx:185-203`. 이 문서(marketingRequests)를 읽는 코드는 저장소 전체에서 `firestore.rules:107`과 위 저장 한 곳뿐(`.ts/.tsx/.mjs` 전수 검색, `functions/src/` 0건). "진행상황을 관리하세요" 문구 `MarketingCenterPage.tsx:224`.
- 고칠 방향: 접수되면 운영 사무실로 문자 한 통(기존 `sendSms`가 있다). 마케팅 센터 아래에 "보낸 요청" 목록(날짜·선택 상품·상태 요청됨/연락함/진행 중/완료)을 둔다.

### 2. 카드로 50만 원을 결제해도 그 뒤에 아무 일도 일어나지 않는다
- 심각도: 막힘
- 어디서: 상품 카드의 「카드로 결제」 → 토스 결제창 → 결제 완료 화면
- 무슨 일이: 결제가 끝나면 "신청이 접수되었습니다. 담당자가 연락드립니다"라고 보여 준다. 그런데 서버는 캐럿(AI 이용권) 결제만 처리하고 마케팅 상품은 주문 문서를 '결제됨'으로 바꾸는 것 외에 아무것도 안 한다. 담당자에게 문자·알림이 없고, 마케팅 요청 문서도 안 만들어지고, 사장이 볼 결제 내역 화면도 없다. 「돌아가기」를 누르면 마케팅 센터가 결제 전과 똑같이 보여서 결제가 된 건지조차 화면으로 확인할 수 없다.
- 근거: 승인 뒤 처리 `functions/src/payments/toss.ts:205-228`(220~227줄에서 `kind === 'carat'`만 지급, 마케팅 분기 없음). `toss.ts` 전체에 `sendSms`·알림 호출 0건. 완료 문구 `src/pages/PaymentResultPage.tsx:80-82`, 돌아가기 `85-90`. 결제 내역(`agencies/{id}/payments`)을 읽는 화면 `src/` 0건.
- 고칠 방향: 마케팅 결제가 승인되면 운영 사무실 문자 + 요청 문서 자동 생성(상태 '결제 완료'). 마케팅 센터에 "결제·신청 내역" 칸을 두고 영수증 링크를 붙인다.

### 3. "최종 금액은 상담 후 확정"이라면서 바로 옆에 즉시 결제 버튼이 있다
- 심각도: 위험
- 어디서: 상품 카드(카드로 결제) ↔ 견적 상자 아래 작은 글씨
- 무슨 일이: 견적 상자 밑에 "최종 금액은 상담 후 확정됩니다"라고 적혀 있는데, 같은 화면 위쪽 카드에는 「카드로 결제」가 있어 상담 없이 50만 원이 바로 나간다. 사장은 "상담하고 정하는 거 아니었나"가 된다. 네이버 상품은 "광고비는 별도 실비"인데 결제 뒤 광고비를 누구에게 어떻게 내는지 설명이 없다.
- 근거: 상담 후 확정 문구 `src/pages/MarketingCenterPage.tsx:408-411`. 즉시 결제 버튼 `295-306`. "광고비 별도 실비" `63`.
- 고칠 방향: 둘 중 하나로 정한다. 상담 뒤 결제라면 버튼을 "상담 먼저"로 바꾸고, 즉시 결제라면 "이 금액이 최종"임을 카드 위에 적고 광고비 납부 방법을 한 줄 붙인다.

### 4. 들어오자마자 '네이버 검색노출 50만 원'이 이미 골라져 있다
- 심각도: 위험
- 어디서: 마케팅 센터 첫 화면, 견적 상자
- 무슨 일이: 아무것도 안 눌렀는데 견적에 "초기 비용 500,000원"이 들어 있다. 홈페이지 무료 제작만 물어보려던 사장이 「상담 요청 접수」를 누르면 50만 원짜리 요청이 나간다. 선택된 카드의 테두리 색이 살짝 다를 뿐이라 휴대폰에서는 골라져 있는지 알아보기 어렵다.
- 근거: 기본 선택값 `src/pages/MarketingCenterPage.tsx:125` (`useState(['naver-seo'])`). 선택 표시는 테두리·체크 아이콘뿐 `275-277`.
- 고칠 방향: 기본 선택 없음. 견적 상자는 고른 게 없으면 "위에서 고르세요"만 보여 준다(이미 그 문구가 있다, `390`).

### 5. "홈페이지에 넣기"가 어디를 눌러 어떻게 하는지 없다 — 네이버 모두·카페24·워드프레스 각각 다른데 한 줄뿐
- 심각도: 답답
- 어디서: 홈페이지 요건 점검 위젯 → "홈페이지에 넣기"
- 무슨 일이: 안내가 "삽입 코드 복사를 누른 뒤 홈페이지 관리자에게 전달하거나 편집기의 원하는 자리에 붙여 넣으면 됩니다" 한 문장이다. 사장은 자기 홈페이지가 무엇으로 만들어졌는지도 잘 모른다. 어떤 화면의 어떤 메뉴를 열어야 하는지, 관리자에게 뭐라고 말해야 하는지(예: "이 두 줄을 상담 안내 페이지 아래에 넣어 주세요") 없다. "저희가 만들었다면 말씀만 주시면 넣어 드립니다"인데 어디에 말하는지 — 버튼·전화·링크 — 아무것도 없다. 복사 버튼은 2초간 "복사됐습니다"만 보여 주고 다음 할 일을 이어 주지 않는다. (추측, 일반 지식) 네이버 모두(modoo!)는 iframe·스크립트 삽입 자체가 안 되고, 워드프레스닷컴 무료 요금제는 스크립트를 지운다. 삽입 코드는 iframe 한 덩어리 + 높이 맞추는 스크립트 한 덩어리인데, 스크립트를 못 넣는 편집기에서는 iframe만 넣어도 동작한다(높이 760으로 고정되고 안쪽 스크롤)는 안내가 없다.
- 근거: 안내 문구 `src/pages/MarketingCenterPage.tsx:322-326`, 복사 버튼 `328`, 삽입 코드 두 덩어리 `104-111`(iframe `min-height:760px` `107`, 높이 스크립트 `108-109`).
- 고칠 방향: "내 홈페이지는 어디서 만들었나요?"를 고르게 하고(직접 제작·카페24·워드프레스·네이버 모두·모름), 각각 어느 메뉴에서 어떻게 붙이는지 3~4줄과 "관리자에게 보낼 문장"을 미리 써 준다. "말씀만 주시면"에는 전화번호나 요청 버튼을 붙인다. 네이버 모두는 "안 됩니다, 대신 점검 링크를 버튼으로 거세요"라고 미리 알려 준다.

### 6. 끼워 넣은 위젯이 내 홈페이지와 색·글씨체가 다르고, 남의 회사 이름이 보인다
- 심각도: 답답
- 어디서: 업체 홈페이지 안에 뜬 점검 위젯
- 무슨 일이: 위젯은 연한 녹회색 배경, 흰 카드, 진녹색 버튼, 프리텐다드 글씨체로 고정이다. 사장 홈페이지가 분홍이든 남색이든 그대로 박힌다. 색·글씨체를 바꿀 방법이 없다(삽입 주소에 붙일 수 있는 값은 업체 ID와 이름뿐). 게다가 위젯 맨 아래 "점검 도구 제공 weddingCORE", 동의 문구에 "weddingCORE는 전달과 기록을 위해서만 보관하며"가 보여서 손님 눈에는 남의 회사가 두 번 나온다. 사장은 "우리 손님인데 왜 다른 회사 이름이 뜨냐"가 된다.
- 근거: 배경색 `src/pages/EmbedCheckPage.tsx:40`(`bg-[#f6f7f3]`), 흰 카드 `src/styles/globals.css:76-78`, 진녹색 버튼 `92-94`, 글씨체 `8`. 삽입 주소 값 `src/pages/MarketingCenterPage.tsx:100-102`. weddingCORE 노출 `EmbedCheckPage.tsx:53`, `src/features/quickCheck/QuickCheck.tsx:239`.
- 고칠 방향: 최소한 주 색상 하나(`&color=`)와 배경 투명 옵션을 주소 값으로 받는다. 손님 화면의 "weddingCORE"는 업체명으로 바꾸고, 도구 제공 표시는 아주 작게 한 곳만.

### 7. 위젯 안에서 「결과 보기」를 누르면 결과가 화면 위쪽에 나오는데 손님 눈은 아래에 머문다

### 8. 손님이 동의하는 "업체 이름"이 주소 뒤에 붙은 글자 그대로다 — 아무도 확인하지 않는다
- 심각도: 위험
- 어디서: 위젯 결과 화면 → "이 결과로 상담 받기" 동의 문구, 공개 /check 화면 상단 문구
- 무슨 일이: "성함·연락처와 위 점검 결과를 상담 연락 목적으로 ○○에 전달하는 데 동의합니다"의 ○○는 주소 뒤 `name=` 값이다. 삽입 코드를 만들 때 넣은 상호가 그대로 굳어서, 사장이 상호를 바꾸거나 오타가 나면 손님은 엉뚱한 이름에 동의한다. 주소를 아는 사람은 누구나 이름을 바꿔 붙일 수 있다. 서버는 진짜 업체명을 알고 돌려주는데 화면은 그 값을 쓰지 않는다.
- 근거: 주소 값 읽기 `src/pages/EmbedCheckPage.tsx:24`, `src/pages/QuickCheckPage.tsx:48`. 동의 문구 `src/features/quickCheck/QuickCheck.tsx:238`, 상단 문구 `QuickCheckPage.tsx:85`. 서버가 진짜 이름을 돌려줌 `functions/src/consult/index.ts:271, 307` — 화면은 미사용.
- 고칠 방향: 위젯이 열릴 때 업체 ID로 서버에서 상호를 받아 표시한다(짧은 조회 함수 하나). 주소의 `name=`은 없앤다.

### 9. 동의 문구에 보관 기간·거부권·처리방침 링크가 없고, 범죄경력까지 넘어가는데 처리방침에는 그 항목이 없다

## 확신이 낮은 항목

- **iframe 허용 헤더가 실제로 먹는지.** 이 사이트는 Cloudflare Pages가 아니라 Workers(정적 자산 방식)로 배포된다(`wrangler.jsonc:16-25`). `public/_headers`는 전체 경로에 `X-Frame-Options: DENY`와 `frame-ancestors 'none'`(남의 사이트에 끼워 넣기 금지)을 걸고, `/embed/*`에서만 `!` 표기로 떼어 낸다(`public/_headers:7, 9, 17-22`). Workers 정적 자산이 Pages와 같은 `_headers` 문법(특히 `!` 제거)을 그대로 지원한다고 알고 있으나 실배포에서 확인한 흔적은 저장소에 없다. 만약 안 먹으면 위젯은 모든 업체 홈페이지에서 빈 회색 칸으로 뜬다(막힘). 실제 업체 사이트 한 곳에서 한 번 눌러 보면 끝난다.
- **7번(결과 보기 뒤 스크롤)** 은 코드상 부모 화면을 올리는 처리가 없다는 것까지가 사실이고, 손님이 실제로 어떻게 느끼는지는 홈페이지 구조(위젯이 페이지 어디에 있는지)에 따라 다르다.
- **5번의 플랫폼별 동작(네이버 모두 불가, 워드프레스닷컴 스크립트 제거)** 은 코드가 아니라 일반 지식이다. 각 플랫폼에서 직접 붙여 봐야 확정된다.
- **삽입 코드 복사 시점의 상호.** 업체 이름은 화면이 열린 뒤 뒤늦게 읽어 오는데(`src/pages/MarketingCenterPage.tsx:137-147`) 복사 버튼은 그 전에도 눌린다. 아주 빨리 누르면 이름 없는 주소가 복사되어 손님 동의 문구가 "해당 업체"로 뜰 수 있다. 8번을 고치면 같이 사라진다.
- **마케팅 요청을 직원(staff)도 보낼 수 있다.** 저장 규칙은 쓰기 권한이 있는 구성원 전부를 허용한다(`firestore.rules:109`). 카드 결제는 대표·관리자만이다(`functions/src/payments/toss.ts:81-83`). 50만 원짜리 요청을 직원이 대표 모르게 보낼 수 있는지는 운영 방침에 달렸다.
