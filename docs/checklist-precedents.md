# 체크리스트 — 판례·재결례를 실무 화면에 연결

목표: 수집만 해두고 아무도 못 보는 판례 574건(법원 판례 225 · 행정심판 재결례 349)을
업체가 서류 준비 단계에서 실제로 쓰게 만든다.

지금 상태는 "모아놓고 안 쓰는 것"이다. `precedents` 컬렉션에 저장되어 있고 요건별
태깅(`requirements`)까지 끝났는데, 보안 규칙조차 없어 클라이언트에서 읽을 수 없다.

## 왜 하나

업체가 알고 싶은 것은 "이 고객이 어디서 걸릴까"다. 소득이 아슬아슬한 고객을 앞에 두고
"소득요건으로 거부된 사례가 실제로 어떤 모양이었는지" 볼 수 있으면 서류 준비의 방향이
잡힌다. 재결례에는 **처분청이 왜 거부했고 왜 유지·취소됐는지**가 이유·재결요지에 그대로
들어 있어 판례보다 실무에 가깝다.

## 손대지 않는 것

- 수집·태깅 로직(`precedents.ts`, `tagRequirements.ts`) — 이미 돌아간다
- 저장 구조 — 필드를 바꾸면 574건을 다시 받아야 한다
- 요건 정의(`visaRequirements.ts`) — 태깅 키가 여기 묶여 있다

- [x] 상세 보기 — 요지·주문·참조조문·본문, 법제처 원문 링크
- [x] 업체 사이드바 진입점

- [x] 출처(법제처) 링크를 사건마다 노출 — 실재 확인 가능해야 한다

### 4단계 · 검증
- [x] 웹 빌드 + 함수 빌드 + 타입검사
- [x] SaaS 점수 유지(100)
- [x] 배포 후 실제 건수·요건별 분포 확인

## 다음으로 미루는 것

- 고객 상세에서 그 고객의 요건에 걸린 사례를 바로 보여주기 (연결이 먼저)
- 사람 검수(`requirementConfidence: 'reviewed'`) 화면 — 변호사 워크벤치에 붙일 일
- 유학 요건 태그 노출 — 유학은 KoAdmit으로 이관했다

## ⚠ 다음에 반드시 볼 것 — 태깅률이 25%다

**574건 중 428건(75%)이 어느 요건에도 연결되지 않았다.** 요건 필터를 누르면
146건 안에서만 걸러진다. 업체가 "소득요건"으로 좁히면 10건밖에 못 본다.

원인은 `tagRequirements.ts`의 판정 기준으로 보인다. 사건명·요지에 걸린
3점 이상만 `requirements`(강한 연결)로 넣고, 그 아래는 `requirementsWeak`에
들어가는데 **화면에서 weak를 전혀 쓰지 않는다.**

손볼 수 있는 순서
1. `requirementsWeak`를 화면에서 "관련 있을 수 있음"으로 함께 보여준다 (코드 변경 작음)
2. `REQUIREMENT_HINTS`의 실마리 낱말을 보강한다 — 특히 안내프로그램 0건은
   낱말이 본문 표현과 안 맞는다는 뜻이다
3. 가중치(`WEIGHT`)와 3점 기준을 다시 본다

**단, 기준을 낮추면 무관한 사건이 섞인다.** 한 번 섞이면 걸러내기 어려우므로
`requirementsWeak`를 별도 표시로 노출하는 1번이 가장 안전하다.

## 태깅 개선 결과 (2026-08-29)

앞서 적은 세 가지 중 **1번만 하고 2·3번은 하지 않았다.** 실측해보니 전제가 틀렸다.

### 1. 약한 연결 노출 — 했다. 효과가 컸다

| 요건 | 강한 연결만 | 약한 것 포함 |
|---|---:|---:|
| 초청인 소득요건 | 10 | 58 |
| 혼인의 진정성 | 37 | 88 |
| 의사소통 | 11 | 72 |
| 주거요건 | 3 | 52 |
| 초청 제한 | 6 | 64 |
| 체류 실태 유지 | 100 | 343 |
| 자격변경 적격 | 63 | 117 |

기본은 강한 연결만 보여주고, "본문에서만 언급된 사건도 포함"을 켜면 약한 쪽이 들어온다.
약한 연결은 점선 테두리에 물음표를 붙여 구분한다.

### 2. 낱말 보강 — 하지 않았다. 오탐만 늘린다

후보 낱말을 실제 본문에서 세어 보고 문맥을 확인했더니 대부분 무관했다.

- **`생계유지`** (본문 29건) — 5건을 열어보니 2건은 귀화 요건, 나머지는 난민 취업·
  중개업소 영업정지 사건이었다. F-6 소득요건과 무관하다.
- **`통역`** (본문 27건) — 4건 중 3건이 재판 통역인 이야기였다.

⇒ 낱말을 늘리면 무관한 사건이 섞인다. 한 번 섞이면 걸러내기 어려우므로 넣지 않는다.

### `국제결혼 안내프로그램`은 낱말 문제가 아니었다

`국제결혼 안내프로그램`·`국제결혼안내프로그램`·`안내프로그램`·`안내 프로그램`·
`소양교육` — **전부 574건 어디에도 없다.** 데이터에 그런 사건 자체가 없는 것이다.
수집 질의(`CASE_QUERIES`)에도 관련 항목이 없다. 애초에 이수하면 끝나는 요건이라
행정심판·소송으로 갈 일이 드문 것으로 보인다. 낱말을 아무리 고쳐도 0건이다.

### 3. 가중치·기준 조정 — 하지 않았다

1번으로 이미 해결됐다. 3점 기준을 더 낮추면 위 2번과 같은 오탐이 강한 연결로
올라온다. 강·약 두 단계를 화면에서 구분해 보여주는 지금 구조가 더 안전하다.

### 대신 한 것 — 빠진 요건 2종 추가

미연결 사건을 열어보니 **귀화·국적 48건, 영주(F-5) 9건**이 요건 체계에 항목이
없어서 분류되지 못하고 있었다. 이 둘은 결혼이민자가 F-6를 졸업하는 두 갈래이고
우리 사업의 최종 상품이다(연장 → 영주·귀화).

`naturalization`(간이귀화 적격)과 `permanent_residency`(영주 적격)를 추가하고
태깅을 다시 돌렸다.

- 강한 연결: **귀화 54건 · 영주 14건**
- 미연결: 428건 → **97건**
- 전체 연결률: 25% → **83%**

남은 미연결 97건은 난민 30건, 출입국관리법위반(형사) 18건, 외국인근로자 13건 등
**F-6와 무관한 사건**이다. 굳이 요건에 연결할 필요가 없다. 다만 수집 단계에서
`하천공작물(보)설치공사준공검사증발급처분취소` 같은 명백한 오탐도 섞여 있어,
수집 정확도는 별도 과제로 남는다.

두 요건은 `status: 'draft'`다 — 근거 조문은 달았으나 변호사 검수 전이다.
